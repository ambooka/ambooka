# ambooka.dev Portfolio Platform

**Role:** Software Engineer
**Status:** Live and actively maintained

## Problem

A static résumé could not present professional experience, completed projects, technical evidence, case studies, and role-specific résumé variants in one consistent system. The portfolio also needed to prevent unsupported future capabilities from being mistaken for delivered work.

## Solution

I built a full-stack portfolio platform using Next.js, TypeScript, Supabase, and PostgreSQL. Content is structured around résumé-backed evidence and administered through authenticated management screens.

Key capabilities include:

- Database-backed professional profile, experience, education, skills, and projects
- Completed-project catalogue with business context and implementation details
- Role-specific résumé variants for software, backend, full-stack, and IT-systems opportunities
- GitHub repository integration
- Dynamic case-study and SEO metadata generation
- Playwright end-to-end test coverage
- Repeatable database reset and targeted content synchronization

## Content model

The portfolio separates four kinds of evidence:

- Employment experience from the supplied résumé
- Client and academic projects from the supplied résumé
- Public repository evidence from this portfolio
- Measurable operational impact, such as KES 1M+/month payment volume, 70+ staff supported, 300+ workers supported, 40+ workstations configured, and a DHCP issue affecting 200+ devices

Anything outside those categories is excluded from public positioning until completed and verifiable.

## Result

Recruiters receive a focused account of completed software, backend, payment, ERP, infrastructure, and computer-vision work without internal planning language or inflated capability claims.
